# 无限画布平台 — 实施方案（管理层）

## 1. 项目概述

基于开源项目 TwitCanva（Apache 2.0 许可证，255 Stars）二次开发，构建全新的 AI 创意画布平台。用户在一个无限拖拽的画布上，自由组合图片生成、视频生成、素材引用和文本备注，像搭积木一样编排创意流程。

**本项目全程采用 AI 辅助开发模式**（Codely CLI / Claude Code），由 AI 完成代码编写、调试、测试，人工负责需求把控和验收。这意味着开发速度更快、人力成本更低，同时代码质量通过 AI + 人工双重把关。

## 2. 与旧版（Narrix）的对比优势

### 2.1 用户体验对比

| 维度 | 旧版 Narrix | 新版无限画布 |
| --- | --- | --- |
| **工作方式** | 每次生成独立操作，生成完就结束 | 画布即工作台，所有创意在一个视图内完成 |
| **对比能力** | 生成结果分散在列表里，无法并排对比 | 多个生成结果在画布上并排展示，一眼对比 |
| **迭代链路** | 需要手动记录参数，重新填写提交 | 节点连线传递，上一个结果直接作为下一个的输入 |
| **创意保存** | 无法保存探索过程 | 画布自动保存，随时回到之前的创意状态 |
| **分镜编排** | 靠外部工具（Excel / 飞书） | 画布上用节点+连线直接编排分镜顺序 |
| **团队协作** | 口头/截图沟通创意方向 | 分享画布，团队直接看到完整创意链路 |
| **素材复用** | 素材在素材页，生成在生成页，来回切换 | 素材直接拖入画布作为节点，和生成结果同框 |

### 2.2 技术架构对比

| 维度 | 旧版 Narrix | 新版无限画布 |
| --- | --- | --- |
| **AI 平台绑定** | 硬编码 ToAPIs，切换需改代码 | **Provider 适配器模式**，新增平台只需加 1 个文件 + 1 条配置 |
| **生成流程** | 同步调用，前端等待 | 异步队列 + 自动轮询，不阻塞画布操作 |
| **数据持久化** | 任务列表式存储，无关联关系 | 画布+节点+连线结构化存储，完整创意链路可回溯 |
| **界面交互** | 表单+列表，每次操作需要多次点击 | 可视化节点拖拽，连线即数据流 |
| **扩展性** | 新增 AI 能力需改后端核心代码 | 新增 AI 能力只需写适配器，核心零改动 |
| **开发模式** | 纯人工编码 | **AI 辅助开发**，效率提升 2-3 倍 |

### 2.3 业务价值对比

| 维度 | 旧版 Narrix | 新版无限画布 |
| --- | --- | --- |
| **使用频次** | 用户只在需要生成时打开 | 画布成为日常工作台，使用频次大幅提升 |
| **创意效率** | 单次生成 3-5 分钟，对比迭代需 15 分钟 | 画布上批量生成+并排对比，5 分钟完成 3 轮迭代 |
| **交付质量** | 生成结果分散，决策依据不充分 | 画布全景展示，决策更直观 |
| **平台粘性** | 功能同质化，替代成本低 | 节点式画布编排能力形成差异化壁垒 |
| **多平台能力** | 仅支持 ToAPIs | 一套系统支持 ToAPIs / Kling / Gemini 等多平台 |
| **开发成本** | 纯人工开发，周期长 | AI 辅助开发，同等功能交付周期缩短 50%+ |

## 3. 核心功能

### 3.1 无限画布

- 无限拖拽平移、滚轮缩放、小地图导航
- 双击空白处创建节点
- 节点拖拽排列、多选、框选
- 右键菜单快捷操作
- 键盘快捷键（复制/粘贴/删除/撤销）

### 3.2 节点类型

| 节点 | 用途 |
| --- | --- |
| 图片生成节点 | 输入提示词 → 调用 AI 生成图片 → 结果显示在节点内 |
| 视频生成节点 | 输入提示词 + 参数 → 异步生成视频 → 节点内播放 |
| 素材节点 | 从素材库拖入已有素材，作为生成参考 |
| 文本节点 | 添加备注、分镜说明、创意描述 |
| 分组节点 | 圈选多个节点分组管理 |

### 3.3 连线系统

- 节点间拖拽连线，表示数据流关系
- 类型感知校验（图片→视频✅ 视频→图片❌）
- 连线可标注关系（"首帧" / "参考" / "尾帧"）

### 3.4 AI 平台可插拔（核心亮点）

- 管理后台配置 AI 平台（endpoint + API Key + 模型列表）
- 画布工具栏一键切换平台
- **新增平台不需要修改业务代码**，只需编写适配器文件 + 数据库配置
- 支持平台：ToAPIs（首批）、Kling AI（预留）、Google Gemini（预留）、OpenAI（预留）

### 3.5 自动保存

- 节点拖拽、数据修改自动保存到数据库
- 画布完整状态持久化，刷新页面不丢失
- 工作流可命名保存，随时加载

### 3.6 提示词中心

- 任何用户可上传提示词模板，上传后全部用户可见
- 按用途分类（图片生成、视频生成、分镜编排、风格变换、角色动画）
- 支持关键词搜索 + 分类筛选 + 按使用次数/最新上传排序
- 选中提示词 → 一键填充到画布节点的描述输入框 → 可二次修改后生成
- 支持变量占位符（如 `{角色描述}在{场景}中`），应用时弹出表单逐个填写
- 画布节点生成成功后，右键可直接「保存为提示词」

### 3.7 技能中心

- 技能 = 提示词模板 + 模型选择 + 生成参数（分辨率/时长/比例/音频等）的完整预设包
- 任何用户可上传技能，上传后全部用户可见
- 按用途分类，支持搜索和排序
- 选中技能 → 一键应用到画布节点（填充所有参数 + 提示词）→ 可微调后生成
- 支持变量占位符，应用时弹出表单填写
- 画布节点生成成功后，右键可直接「保存为技能」（自动带入当前参数）

### 3.8 社区机制

- 每条提示词/技能展示使用次数和点赞数
- 用户可点赞优质内容
- 预览图：上传时可关联示例图，列表页展示缩略图辅助判断效果

### 3.9 创意助手（AI 对话）

- 画布右侧内置 AI 对话面板，帮助用户写/优化提示词、拆解分镜、分析构图
- AI 回复的提示词可一键发送到当前选中的画布节点，或保存到提示词中心
- 对话历史存数据库，刷新不丢失，可创建多个对话
- 支持多用户并发，互不干扰

## 4. AI 辅助开发模式

### 4.1 开发方式

本项目采用 **AI 辅助开发模式**，不同于传统开发流程：

| 环节 | 传统开发 | AI 辅助开发 |
| --- | --- | --- |
| **代码编写** | 开发人员逐行手写 | AI 根据需求文档生成代码，开发人员审核 |
| **调试** | 手动排查 | AI 分析日志定位问题，给出修复方案 |
| **测试** | 手动编写测试用例 | AI 生成测试代码并执行，报告覆盖率 |
| **代码审查** | 人工 Review | AI 先做初步审查，人工复核关键逻辑 |
| **文档** | 单独编写 | AI 在开发过程中同步生成 |
| **部署脚本** | 手动编写 | AI 生成 Dockerfile / docker-compose |

### 4.2 质量保障

| 保障措施 | 说明 |
| --- | --- |
| TypeScript 严格模式 | 编译期类型检查，杜绝低级错误 |
| AI 生成 + 人工审核 | 每段代码先由 AI 生成，开发人员审核后才合入 |
| 自动化测试 | AI 生成单元测试 + 集成测试，CI 自动执行 |
| 逐步交付 | 分 9 个阶段迭代，每阶段可独立验收 |

### 4.3 成本优势

| 维度 | 纯人工开发 | AI 辅助开发 |
| --- | --- | --- |
| 人力投入 | 1 名全栈开发（全职） | 1 名开发人员（把控需求 + 审核 AI 代码） |
| 开发周期 | 30+ 工作日 | 17 个工作日 |
| 代码质量 | 依赖个人经验 | AI 遵循最佳实践 + 人工把关 |
| 文档完整度 | 通常滞后 | AI 同步生成 |

## 5. 技术方案概要

| 维度 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React 19 + TypeScript + Vite | TwitCanva 原有技术栈 |
| 画布引擎 | TwitCanva 自研引擎 | 成熟稳定，30+ 交互 Hooks |
| 后端 | Koa 3 + 模块化路由 | 参考 Narrix 架构 |
| 数据库 | PostgreSQL 16 + Kysely | 结构化存储画布/节点/连线 |
| 异步队列 | Redis + BullMQ | 视频生成任务异步处理 |
| AI 对接 | **Provider 适配器模式** | 核心抽象，支持多平台热切换 |
| 对象存储 | 阿里云 OSS | 生成结果持久化 |
| 部署 | Docker Compose | 一键部署 |

## 6. AI 对接抽象化设计

### 6.1 设计理念

> 新增一个 AI 平台 = 1 个适配器文件 + 1 条数据库配置，业务代码零改动。

### 6.2 架构图

```
画布节点点击「生成」
      │
      ▼
GenerationService（业务层，不感知具体平台）
      │
      ▼
ProviderRegistryService（注册中心，从数据库读取配置）
      │
      ├── ToApisProvider   →  ToAPIs API
      ├── KlingProvider     →  Kling AI API（预留）
      ├── GeminiProvider    →  Google Gemini API（预留）
      └── OpenAIProvider    →  OpenAI API（预留）
```

### 6.3 扩展步骤

| 步骤 | 操作 | 是否需要改业务代码 |
| --- | --- | --- |
| 1 | 编写适配器文件（继承 BaseProvider） | ❌ 不需要 |
| 2 | 在 factory.ts 注册（加一行代码） | ❌ 不需要 |
| 3 | 管理后台添加平台配置 | ❌ 不需要 |
| 4 | 完成，画布自动出现新平台选项 | ✅ 自动可用 |

## 8. 预期效果

### 8.1 效率提升

| 场景 | 旧版耗时 | 新版耗时 | 提升幅度 |
| --- | --- | --- | --- |
| 生成 3 张不同风格的图片对比 | 15 分钟（3 次独立操作+截图对比） | 5 分钟（画布并排生成） | 67% |
| 视频分镜方案探索 | 30 分钟（外部工具编排+逐个生成） | 10 分钟（画布节点编排+批量生成） | 67% |
| 切换 AI 平台测试效果 | 需开发改代码（1-2 天） | 管理后台配置（5 分钟） | 99% |
| 团队评审创意方案 | 截图+文档整理（20 分钟） | 分享画布链接（即时） | 100% |
| 新用户上手生成高质量内容 | 需学习参数搭配（数小时） | 选一个技能一键应用（10 秒） | 99% |
| 写专业提示词 | 自己搜索/试错（20 分钟） | 问创意助手，AI 生成（30 秒） | 97% |

### 8.2 差异化壁垒

- **画布式创意工作台**：从「工具」升级为「工作台」，用户粘性提升
- **多平台 AI 能力**：一套系统支持多平台，不依赖单一供应商
- **可视化编排**：节点+连线的创意流程，竞品不具备
- **结构化创意资产**：画布数据完整保存，可复用、可迭代、可分享
- **技能 + 提示词社区**：用户贡献的预设包形成内容飞轮，新用户开箱即用，降低使用门槛
- **AI 创意助手**：内置对话面板，用户不擅长写提示词也能获得专业级结果
- **AI 辅助开发体系**：后续功能迭代也可用 AI 辅助，持续保持开发效率优势
