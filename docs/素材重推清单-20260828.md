## 三、重推操作方式

已上线的前端功能（v10）或后端批量接口均可：

**方式 A · 管理界面（推荐给用户）**：素材管理 → 批量同步 → 勾选下列素材 → 确认。已同步素材现在允许重新勾选。

**方式 B · 运维直推**：SQL 置 pending 后 BullMQ 直投：

```sql
UPDATE assets SET ark_asset_id = NULL, ark_group_id = NULL,
  ark_status = 'pending', ark_error = NULL, updated_at = now()
WHERE id IN (<批次 ID 列表>);
```
```
docker exec worker 容器 node 直投 sync-asset-status 队列，jobId = asset-sync-{id}
```

**注意事项（依据实测）**：
1. **分批执行**：每批 ≤10-20 个，批次间隔 2-3 分钟，避开 `QuotaWriteQPMExceeded`（写入频率限制）
2. **配额占用**：每次重推在 ToAPIs 素材库**新建一个素材**（旧素材远端不删、继续占配额）。当前已出现 `quota_not_enough` 生成配额不足告警，大规模重推前建议先联系 ToAPIs 确认素材库配额余量（此前有 `QuotaSharedPoolExceeded` 前科）
3. **旧引用失效**：重推后 `pa_` ID 变化，历史视频任务的 replay/草稿中引用旧 ID 的需重新选素材（新任务自动用新 ID）
4. **生效时间**：置 pending → worker 提交 → ToAPIs 审核，单素材约 10-30 秒转 active（今晚实测 10 个约 90 秒全部完成）
5. **漂移风险**：channel 归属会持续漂移（上午失效的傍晚恢复、傍晚失效的深夜恢复），**建议执行前重新实测**；本清单以 2026-08-28 23:50 实测为准
