# Narrix 软件需求规格说明书

| 项目 | 说明 |
| --- | --- |
| 文档编号 | NARRIX-SRS-01 |
| 文档版本 | V1.0 |
| 适用系统 | Narrix 自部署交付版本 |
| 编制依据 | 当前交付源码与页面功能 |

## 1. 项目概述

Narrix 是面向漫剧内容生产流程的自部署管理平台，提供项目工作区、素材组、素材管理、视频生成任务、用户权限、运行态配置和初始化安装能力。系统支持将素材存储在 OSS 私有桶，并按配置同步到火山素材资产库；视频任务通过火山视频生成接口提交和轮询。

## 2. 建设目标

1. 建立统一的内容项目工作区，隔离不同项目的数据。
2. 提供素材组、素材上传、素材同步状态管理能力。
3. 提供视频生成任务创建、查询、统计和结果查看能力。
4. 提供用户账号、项目授权和菜单权限控制能力。
5. 提供自部署安装向导和运行态配置管理能力。
6. 保证 OSS 私有资源通过临时 URL 访问，不直接暴露原始私有地址。

## 3. 用户角色

| 角色 | 权限范围 |
| --- | --- |
| 管理员 | 可访问项目管理、用户管理、系统配置、素材管理、视频任务和统计页面 |
| 普通用户 | 可根据菜单权限访问素材、视频、统计等业务页面 |
| 项目成员 | 在被授权项目范围内访问项目数据 |
| 项目管理员 | 在项目成员权限基础上可管理项目内素材和任务相关数据 |
| 项目查看者 | 可查看授权项目内数据，具体能力受菜单权限限制 |

## 4. 功能需求

### 4.1 初始化安装

系统首次启动后进入安装态，安装向导应支持：

- 获取安装状态和运行环境健康状态。
- 创建超级管理员账号。
- 配置系统名称。
- 校验 OSS 配置。
- 校验火山视频接口配置。
- 校验火山素材资产库 AK/SK。
- 查询或创建默认火山素材组。
- 保存默认素材同步策略。
- 完成初始化后进入登录流程。

### 4.2 登录与会话

系统应支持：

- 用户名和密码登录。
- 登录成功后返回 token、用户信息、可访问项目列表和当前项目。
- 获取当前会话信息。
- 修改当前用户密码。
- 退出登录。
- 未登录访问受保护页面时跳转登录页。

### 4.3 项目工作区

系统应支持：

- 创建项目。
- 查询项目列表和项目详情。
- 更新项目名称、说明、封面素材。
- 归档项目。
- 维护项目成员和成员项目角色。
- 按项目隔离素材组、素材、视频任务和配置视图。

项目编码由系统自动生成，格式为 `PRJ-YYYYMM-000001`。

### 4.4 用户管理

系统应支持管理员：

- 分页查询用户列表。
- 按状态筛选用户。
- 创建用户。
- 更新用户角色、菜单权限、状态、密码。
- 维护用户可访问项目及项目角色。
- 删除或停用用户。

### 4.5 素材组管理

系统应支持：

- 查询当前项目素材组列表。
- 创建素材组。
- 更新素材组名称、排序、同步策略。
- 删除素材组。
- 删除非空素材组时可将素材迁移到目标素材组或未分类。
- 管理素材组与火山素材组的关联。

### 4.6 素材管理

系统应支持：

- 获取 OSS 上传临时凭证。
- 上传图片、视频、音频素材。
- 创建素材记录。
- 查询素材列表、详情。
- 按状态、关键词、上传人、类型、素材组筛选。
- 更新素材组和同步模式。
- 删除素材或解除项目关联。
- 管理素材关联项目。
- 手动触发素材同步。

素材类型包括 `Image`、`Video`、`Audio`。

### 4.7 视频任务

系统应支持：

- 创建视频生成任务。
- 支持首尾帧模式和综合素材模式。
- 支持文本、图片、视频、音频素材作为任务内容。
- 查询视频任务列表和详情。
- 按状态、模式、关键词、时间范围筛选。
- 查看视频任务统计数据。
- 手动同步指定视频任务状态。
- 展示任务状态、结果 URL、失败原因和轮询状态。

任务状态包括 `pending`、`processing`、`succeeded`、`failed`。

### 4.8 系统配置

系统应支持管理员：

- 查询运行态配置。
- 更新配置项。
- 查询火山素材组。
- 创建火山素材组。
- 获取公开品牌配置。

配置项包括火山视频接口、火山素材资产库、OSS、系统名称、Logo、默认同步策略等。

## 5. 非功能需求

### 5.1 安全性

- 所有受保护接口必须校验 token。
- 项目数据访问必须校验项目上下文和项目权限。
- 密钥类配置应按敏感配置处理。
- 不向前端返回 OSS 私有桶原始地址。
- 日志不得输出密码、token、AK/SK、签名 URL 等敏感信息。

### 5.2 可维护性

- 后端采用 routes、controllers、services、schemas、workers 分层。
- 前端采用 api、pages、components、stores、router 分层。
- 数据结构变更通过 migration 管理。
- 接口入参使用 Zod 运行时校验。

### 5.3 可部署性

- 支持 Docker Compose 一键启动完整服务。
- 支持 dev 和 prod 两套环境变量模板。
- 后端、前端、数据库、Redis、worker 独立服务运行。

### 5.4 可观测性

- 后端记录请求日志。
- 后台任务记录处理状态和错误信息。
- 视频任务保存轮询状态字段，便于排查任务长时间处理中问题。
